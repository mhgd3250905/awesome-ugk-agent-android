# 编写完整 SOP

将原始记录或按段提炼的笔记整合成一份完整中文 Markdown 正文。先跨段核对最终目标和纠正；若附有 originalUserInstructions，结合原话判断哪些旧做法已被替代。正文只保留通向最终目标的必要路径，不复述教学流水账。

可以用“目标、准备条件、操作步骤、注意事项、完成检查、待核实”等标题帮助阅读；根据材料取舍，不为凑小节补造内容。通常在 12000 字符左右即可讲清，复杂指南可按需要展开。步骤应让执行者理解操作目的、所在页面、可辨识入口和继续或结束的依据。把尚未证实的结果写成执行时需确认的条件，已知中断与无法确认的关键缺口要可见。

失败或被撤销的尝试放在能帮助理解的纠正说明中，不混入正常路径。必要时提供已知应用名称、适用范围和少量同义任务表达，例如“查看哪些应用有更新”不能扩成“安装所有更新”。

面向执行者表述，不展示内部工具名、UUID、快照 ID、原始 JSON 或一次性像素坐标；需说明来源时可写“教学第几段”。直接给出完整指南，不输出业务 JSON、代码围栏或仅说“已完成”。本阶段不调用工具，草稿随后由审核阶段核对交付。
