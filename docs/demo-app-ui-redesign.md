## 2026-09-27 进入 App 的权限引导

进入主界面时，按真实系统状态依次说明缺失的无障碍、悬浮窗、相机和通知权限。每项均可暂时跳过，“以后再说”或返回键结束本轮；下一次真正从后台进入时重查。采用既有便签底部卡片、猫头鹰和绿色主按钮，浅深色共用 Token；窄屏大字号时顶部分行、正文滚动、底部操作固定。已授权后关闭、系统不再询问时提供对应设置入口；旧历史缺失时保留一次设置兜底。通知同时核对应用总开关与实际提醒分类。功能边界、生命周期及验证证据见 [权限引导规范](demo-app-permission-guide.md)。本阶段沿用 `1.10.0 / 123`，源码以本地收束提交保存，原版本标签保持原位。

权限步骤之后追加“可选建议”卡：后台耗电、自启动及最近任务卡片锁定。两个设置入口分别由用户点击，设置返回继续当前建议；“我已了解，不再提醒”记录阅读版本，跳过仅影响本轮。设置页常驻入口与计时确认的“后台设置”复用此卡。不会把阅读或导航记录显示成系统开关已开启，也不承诺后台常驻；179 项单元测试、12 项仪器测试及模拟器实际往返验证通过。13:55 保留数据安装同一小米真机后，用户反馈“可以了 测试通过”；具体真机操作路径未另行记录，长期后台存活未验证。

## 2026-09-25 悬浮对话与主界面统一

用户指出 App 退到后台后，悬浮对话仍使用旧的大标题、重复状态块、逐步白色卡片和直接铺开的活动日志。`1.10.0` 将悬浮面板改为紧凑对话：单行省略标题、次级状态、三个 48dp 图标入口，正文沿用主聊天画布和 `DemoChatMessageView`，展示最近 12 条消息；完整历史由打开主界面入口承载。Markdown、代码、表格、图片和复制行为使用同一组件，图片预览使用悬浮窗口类型并随面板关闭回收。

过程复用 `DemoChatProcessCardView` 的一行摘要、三点动效和两级轻量记录，放在本轮输入之后、回答之前。两处界面从 `DemoRunState.toChatProcessState()` 得到相同阶段和步骤含义；悬浮窗独立保留用户的展开选择。同会话、同任务下按消息 ID 和步骤 ID 复用 View，状态、日志或输入草稿变化不重建过程。流式回答复用主界面的 64ms 节流输出，已写回的相同回答不重复显示。读者滚离底部后不被新消息强制拉走，需要确认时仍优先定位确认区。

活动记录默认收起，只保留低对比文字入口。白色圆角输入区复用 `SendActionButton`，保留忙时发送排队与独立停止按钮；发送被拒绝保留草稿并显示本次错误，历史成功日志不会被误用为失败原因。标题拖动、右下角缩放、悬浮球收起、外部自动化焦点模式、150ms 防抖 IME 避让和确认回调继续使用既有语义。

新增打开主界面图标取自 [Google Material Icons outlined open_in_new 原始 Android 资源](https://github.com/google/material-design-icons/blob/master/android/action/open_in_new/materialiconsoutlined/black/res/drawable/outline_open_in_new_24.xml)，沿用已打包的 Apache 2.0 许可。没有新增运行时依赖。窄窗口大字体下代码语言标签保持单行省略，读屏保留完整语言名称。真实悬浮窗、键盘、拖动及浅深色验收以根目录 `design-qa.md` 的 `1.10.0` 记录为准。

## 2026-09-25 轻量过程入口与可追溯记录

用户指出主聊天的过程展示占用过大，白底外框、头像、粗黑标题和彩色完成标记让它与最终回答争夺注意力，并提供其他 App 的“动态小点 + 一句进展”参考。`DemoChatProcessCardView` 现从 `DemoChatViews.kt` 提取为独立原生组件，收起态只保留最小 48dp 触控行：24dp 三点动效、15sp 次文字摘要和 18dp 展开箭头。运行摘要按真实阶段更新；完成后保留可展开的静态步骤入口，停止采用中性色。

展开态沿用对话画布底色，移除整块卡片、外框、头像、重复阶段和步数 footer。13sp 正常字重标题、12sp 单行摘要、小状态图标与细连接线形成过程记录。每个步骤独立展开；完整思考、参数和结果保留在 170dp 高的局部滚动区，正文可选择和读屏。新增步骤按 ID 复用已有 View；读者滚离底部时，流式内容不强制拉回底部。收起外层会重置子步骤，再展开从简明列表开始；底部仍有“收起过程”。

`DemoProcessPresentation` 只从阶段和工具名称映射收起摘要，不使用含自由文本的 `detailLabel` 或 `resultSummary`。原始内容留在逐项详情。工具成功或失败后 Runtime 仍忙碌时继续动效，等待用户确认时静止，最终完成/失败/手动停止或组件隐藏、离开窗口时停止。遵从 Android 的系统动画开关；动画帧只更新图标旋转与透明度，不触发布局和读屏播报。

三点、展开、完成、错误、暂停和小圆点使用 [Google Material Icons](https://github.com/google/material-design-icons) 的 Android outlined 原始矢量资源（`ic_process_*`），使用现有 Apache 2.0 许可文件。没有新增运行时依赖。截图与交互验证见根目录 `design-qa.md` 的 `1.9.0` 记录。

## 2026-09-25 便签式确认、计时与全屏提醒

用户选定第二张暖纸便签设计稿后，三种界面共同使用 `TaskNoteUi`：浅色奶油纸、森林绿文字、琥珀倾斜标签、细虚线及探头猫头鹰；深色改用暖深底、浅色文字与浅绿主按钮。2026-09-27 的权限与后台建议卡继续复用此样式，聊天画布仍使用原有 `Ui` Token。标题、任务、倒计时、按钮和表单都是原生 View，图片仅承担角色和装饰。

计时提案从底部进入、向下收回，仅上缘圆角。“等你点头 / 这份安排，确认吗？”明确请求决定，完整任务成为大字主体，间隔采用自然时长并紧邻单次/周期标识；虚线之后说明确认后才开始计时。周期仍说明每轮完成后重新等待、直到停止；排队消息清空提示和后台设置保留。固定底部并排提供“取消 / 确认并开始”，按钮最小 54dp；长内容可在独立内容区滚动，不遮挡按钮。

计时等待从顶部进入、向上收回，仅下缘圆角。沿用透明全屏窗口和一次状态栏 inset，纸色覆盖到状态栏背后。琥珀“正在等待”标签与已完成轮次在顶行，剩余时间和猫头鹰并排，下方依次为确定进度、任务摘要、固定的危险色“停止任务”。等待摘要最多两行并保留完整读屏描述，完整任务和上轮结果由主对话承载。正常竖屏内容完整直显；短高度窗口先为操作区保留实测高度，再允许正文独立滚动，避免停止按钮被挤出。

全屏提醒沿用同一纸面和角色：固定顶部“重要提醒”与 48dp 关闭入口，正文大标题、角色、段落和提醒缘由由留白与虚线组织。短内容在可滚动区域居中，长内容自然滚动。仅在 Agent 实际提供 actions/form 时显示“等你回应”；真实操作与表单仍按原协议回传。底部固定“打开对话”，存在回应控件时使用次按钮以突出实际回应。关闭不表示确认或完成。四种 accent 继续用于局部语义标记。

图像资源 `brand_owl_note.png`、`note_marker_underline.png` 由内置 ImageGen 依据选稿和已有品牌猫头鹰生成：前者提示为“绿色圆身、黑眼罩、绿圆眼、轻歪头、双翼搭在隐形纸缘、透明背景”；后者提示为“琥珀色两段手写短划线、末端两笔放射标记”。下划线原图为暖纸色 RGB，`TaskNoteUi.marker` 以蓝通道生成透明墨迹遮罩并按主题着色，避免深色出现浅底矩形。时钟和关闭使用 [Google Material Icons](https://github.com/google/material-design-icons) 的原始 Android 矢量资源，Apache 2.0 许可随 APK 放在 `assets/licenses/material-icons-LICENSE.txt`。

## 2026-09-02 悬浮窗软键盘避让基线（当前悬浮窗键盘基线）

本节随 `1.0.3 / versionCode 103` 生效（`1.0.4` 延续），只改变跨 App 悬浮窗在软键盘弹出/收起时的行为，不改变主界面 IME 布局、视觉 Token、SDK 能力或权限边界。

- 悬浮窗不依赖系统 `ADJUST_RESIZE` / `ADJUST_PAN`（实测对 `TYPE_APPLICATION_OVERLAY` 均无效）；`softInputMode` 保持 `SOFT_INPUT_STATE_UNCHANGED or SOFT_INPUT_ADJUST_NOTHING`。
- 三层 IME 检测：`onApplyWindowInsets` 缓存 + 150ms 防抖 → `imeBottom > 0` 精确换算键盘顶 → IME 可见但无值时按屏高约 58% 估算兜底；键盘收起后恢复 `preImeY` 锚点。不挂 `WindowInsetsAnimation.Callback`（会使 overlay 丢失 ime 数值）。
- 交互验收（模拟器 `ugk_dev_api35_smooth` + `ImeAvoidanceTest` 12/12）：贴底悬浮窗弹键盘上移至理论位 ±10px、收键盘复位 0 误差、三连开关零漂移、不与键盘重叠时不移动、收起再展开无跳变。
- 边界：估算兜底对第三方浮动键盘/横屏未验证（方向保守）；API 24-29 差值法无老设备实测。本节取代下方"前置功能验收基线"中悬浮窗以 `ADJUST_RESIZE` 收缩到键盘上方的旧验收口径。

## 2026-09-03 贴顶钳位下的 IME 高度压缩（1.0.5）

展开态悬浮窗已贴住 48dp 顶部钳位且平移后仍与键盘重叠时，压缩窗口高度，使底部保持在 IME 上方 8dp；压缩受最小/最大高度约束，不会增高。键盘关闭时恢复用户原始位置与高度；IME 打开期间调整尺寸后，恢复高度采用新尺寸。版本与验收证据见 `demo-app-version-ledger.md` 的 1.0.5 条目。

## 2026-08-29 微信式视觉重构（消息色彩基线；过程样式已由 1.9.0 更新）

本阶段起于 `0.7.1` 的同版本视觉 checkpoint，并在完整验收后保存为 `0.8.0 / versionCode 10`；只改变 `:demo-app` 的视觉表达与状态语义，SDK 能力、权限、依赖和 API 配置边界不变。

| 区域 | Light | Dark | 语义约束 |
|---|---|---|---|
| 应用背景 | 暖白/米白低对比背景 | 深碳灰背景 | 作为安静的对话画布 |
| 用户消息 | 右侧主题绿气泡 | 右侧深绿主题容器 | 只表达用户意图与发送动作 |
| AI 回复 | 左侧白色/中性气泡 | 左侧深灰中性气泡 | 不使用品牌绿，保持阅读主次 |
| 过程与证据 | 透明背景的一行过程及轻量记录；代码、表格保留中性卡片 | 同样的轻量记录；代码、表格采用深灰中性容器 | 工具结果不与聊天气泡竞争，过程样式以 1.9.0 为准 |
| 状态与操作 | 绿色、琥珀、红色按语义使用 | 同一语义在深色容器中适配 | 成功、警告、危险、禁用彼此区分 |

- 品牌资产保持同一猫头鹰语汇：launcher 沿用原品牌图，透明变体用于 App 内助手头像、空状态和悬浮窗入口；不把临时截图或会话信息写入仓库。
- 顶栏与 composer 采用低噪声、无厚重外框的布局；首页顶栏只保留会话入口、运行状态和设置入口，主题切换集中在设置页，设置入口使用标准齿轮矢量图标；输入框、发送/停止按钮、按压态和禁用态共享同一套状态 Token。
- 设置页使用中性分组卡片、紧凑选择 Chip 和明确的已选/停用语义；悬浮窗折叠/展开、Markdown、代码/表格卡片与主聊天复用同一套 Light/Dark Token。
- 过程摘要、工具步骤、代码和表格属于证据层，默认使用中性颜色；用户/AI 气泡属于对话层，保持右绿左中性的稳定视觉顺序。
- 绿色预算固定为：用户气泡、主要动作、已选控件和成功状态；等待确认使用 warning，危险或不可逆操作使用 danger，失败不伪装成成功。

- 用户和助手消息渲染分离，工具过程不再追加到普通助手文本中。
- 运行过程默认显示一行摘要，可点击展开工具步骤、结果摘要、错误和耗时。
- 过程入口采用单行与两级展开：外层展开后步骤默认收起，点击单个步骤查看完整详情；顶部摘要行和底部均提供收起整个过程的入口，样式以 `1.9.0` 的轻量过程记录为准。
- 展开过程后按步骤时间线展示可观察事件、状态图标和完整结果，不把长结果压成固定行数。
- 输入框支持多行、草稿恢复、空闲时随内容启用发送、运行中切换为停止，以及键盘自适应。
- 软键盘弹出时，消息流和输入区跟随 IME inset 重新布局，输入内容和发送按钮保持可见。
- 聊天正文不因气泡行数或字符数被 UI 自动替换为省略号，长消息由外层消息流滚动阅读。
- 本地会话管理：新建、切换、重命名、删除，默认保存最近的有界消息内容。
- 无配置 API、无障碍未开启、悬浮窗未授权等情况使用非阻塞状态提示。
- 跨 App 悬浮窗：获得“显示在其他应用上层”权限后，离开主界面即显示可拖动状态胶囊，不要求先发送任务；空闲时可直接从悬浮窗发送消息。展开后可查看最近 12 条消息及当前过程、发送消息、停止任务、返回主界面或隐藏悬浮窗；完整历史从主界面进入。展开面板仅标题状态区域负责移动，按钮保留点击语义，右下角使用加粗圆弧提示缩放，不额外放置图标，最小约 `280dp × 240dp`。
- 悬浮窗与主界面使用同一运行状态模型；运行中从悬浮窗发送的消息进入队列，不直接打断当前 Agent 操作。
- 悬浮窗展开内容遵循时间线：本轮用户消息（如有）→ Agent 过程 → Agent 回答；排队状态及默认折叠的活动记录位于消息流之后。回答长文本保持完整并由面板滚动查看。
- 重要提醒临时接管悬浮显示区域，占满应用可用屏幕；右上角固定关闭、底部可打开对话，关闭后恢复普通悬浮状态。Agent 可选择固定配色、有限的纯文本内容元素、最多 3 个真实按钮及一个单行表单；App 负责布局、关闭入口和点击/提交回传。控件事件在原会话排队成为新的 `SDK_EVENT` 回合，关闭不表示确认或完成；系统状态栏、导航栏和关键界面仍由 Android 控制。协议见 [android-agent-attention.md](android-agent-attention.md)。
- 单次延时或固定间隔周期任务经用户确认后，在主对话显示阻塞层和“停止任务”；确认态突出完整任务、自然时长与主操作，等待态突出大号 tabular 数字倒计时、确定进度、周期已执行次数和紧凑摘要，上轮完整结果留在主对话。三种便签界面使用随 `Ui.isDark` 切换的 `TaskNoteUi` Token。切后台或锁屏不主动取消，返回页面后从进程级状态重建弹窗。每次到点都作为同一对话的新用户消息进入原 Agent 运行链路；周期任务执行完后继续等待下一轮，直到用户停止。协议见 [demo-delayed-conversation.md](demo-delayed-conversation.md)。
- 缩放触控层置于内容层下方，发送按钮和输入框优先响应；右下角圆弧只承担尺寸调整提示和拖动入口。
- 授权模式：设置页提供默认关闭的“全授权模式”，开启后持久化跳过高影响操作确认，并在主界面持续显示安全提示；该模式只建议用于受控测试设备。
- 后台确认：Agent 请求确认时，前台使用 Activity 对话框；Activity 进入后台后迁移为悬浮窗内的确认卡片，显示完整标题、正文和按钮，回到前台后再迁回对话框。
- 不新增生产依赖，不读取或输出真实 API Key，不把真实 LLM 调用加入自动化测试。

## 状态优先级

| 优先级 | 内容 | 默认呈现 |
|---:|---|---|
| 1 | 用户与助手消息 | 主界面显示会话；悬浮窗显示最近 12 条并按任务时间线排列 |
| 2 | 发送/停止、等待确认、失败 | 始终可见 |
| 3 | 当前运行阶段 | 一行过程摘要 |
| 4 | 工具名、耗时、结果摘要 | 点击过程摘要展开 |
| 5 | 完整工具输入输出 | 仅在详情中展示，必要时支持复制 |
| 6 | API、权限、Runtime 能力 | 顶栏状态或设置页；缺失权限在空闲前台提供可跳过引导 |

## 交互状态验收

| 场景 | 预期 |
|---|---|
| 空会话 | 有明确的开始提示和 2–3 个本地示例入口，不显示空白终端区域 |
| 输入 | 可输入多行，发送按钮随内容启用，键盘不遮挡输入区 |
| 运行中 | 主界面发送入口切换为停止；悬浮窗保留发送排队并另显停止。过程默认收起；读者在底部时跟随新内容，离开底部后保留阅读位置 |
| 工具调用 | 显示“正在调用工具”，不把原始 JSON 插入普通聊天正文 |
| 确认 | 前台显示高影响操作确认上下文；后台显示悬浮窗确认卡片；取消后显示可理解的取消结果 |
| 工具完成 | 显示成功/失败和结果摘要，详情可展开 |
| 最终回答 | 清晰显示为助手回合，可继续发送下一条消息 |
| 失败/停止 | 显示原因和可选重试，不伪装成正常完成 |
| 新建会话 | 当前会话先保存，新的 AgentSession 与消息流独立 |
| 返回前台 | 当前会话、草稿和界面状态不表现为重启 |
| 无权限 | 主聊天仍可用；每次真实前台进入按状态展示可跳过引导，系统不再询问时提供设置入口，忙碌时延后 |
| 悬浮窗任务完成 | 本轮过程位于用户消息与助手回答之间；排队状态和折叠活动记录位于消息流之后。发送按钮仍可点击，圆角缩放区不遮挡输入操作 |
| 重要提醒 | 占满可用屏幕、内容可滚动，右上角关闭始终可见；关闭后回到先前的悬浮状态或主对话，不留遮挡层 |
| 重要提醒按钮 | 点击一次后关闭提醒，并在原会话显示对应用户操作和 Agent 的后续答复；重复点击不启动第二轮 |
| 重要提醒表单 | 输入非空短文本后提交；键盘出现时输入区可用，提交值回到原会话；点关闭不提交 |

## 模块计划

1. `DemoConversationStore`：本地会话数据、JSON 编码、有界保存和 CRUD。
2. `DemoRunState`：把 `AgentEvent` 映射为稳定的 UI 状态和过程步骤。
3. `MainActivity`：只负责生命周期、运行协调器绑定和 UI 组装，消息/过程渲染使用独立组件。
4. `DemoAgentRunCoordinator`：持有进程级 Agent Job、运行代次、队列和完成待处理结果，Activity 重建只重新绑定观察者。
5. `AgentFloatingWindow`：消费同一运行状态摘要；活动记录仅作为兼容性辅助信息，不与最终回答混为同一正文层。
6. 测试：Store/排序单元测试、运行状态 reducer 单元测试、Activity 生命周期与现有 Agent 集成回归。

## 性能与安全边界

- 保持原生 View 实现，不为一次 Demo 重构引入新的 UI 框架或生产依赖。
- 主线程只做有限的 View 更新；运行逻辑移出 Activity，长文本与历史均有界，持久化仍需在真机长会话中关注帧耗时。
- 过程和历史都使用有界列表，防止长期测试导致布局无限增长。
- 该界面不把 Terminal Runtime 描述为安全沙箱；工具确认和共享 UID 边界继续由 SDK 负责。

## 2026-08-25 屏幕自动化调优

- `screen_read_ui_tree` 现在返回 `screenWidth`、`screenHeight`、非自身 `windowCount` 和 `truncated`，并支持有界的 `max_nodes`（默认 200，最多 500）。Agent 必须在 `truncated=true` 时继续滚动或请求更大的有界结果，不能据此直接判断目标不存在。
- UI 树读取和屏幕动作路径补齐 `AccessibilityNodeInfo` 回收，减少连续读屏/操作时的节点资源积累；`screen_perform_action` 对未知 action 和缺少 `set_text.text` fail-closed，避免误清空输入框。
- `screen_gesture` 根据当前屏幕尺寸计算滑动终点，拒绝缺少或越界的起点，不再依赖固定 `1080×2400` 坐标；手势回调等待改为可取消的协程等待，超时不会阻塞 Tool 执行线程。
- Agent instructions 改为使用最近一次读屏返回的屏幕尺寸和相对位置计算手势坐标。

本轮已在 Pixel 8 / Android 17 Preview 与 SM-A526U1 / Android 14 上完成 Debug 仪器回归，各 `14/14`；坐标计算、边界拒绝和输入保护由 JVM 测试覆盖。两台设备当时均未启用本 Demo 的 AccessibilityService，因此微信/设置/浏览器等跨 App 的真实无障碍操作仍需用户手动开启服务后另行验收。
