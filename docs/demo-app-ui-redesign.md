## 需求结论

当前 Demo 的问题不是单独的颜色或按钮数量，而是信息架构没有区分四类内容：用户意图、助手回答、Agent 运行进度、工具证据。本轮以用户提供的微信界面为交互秩序参考，采用成熟 IM-style 的聊天优先模型，但不复制商标、图标或内部实现：聊天流是主界面，过程是可展开的辅助层，会话历史是次级导航。

聊天历史、删除会话和设置继续作为独立能力；本轮仅借鉴成熟 IM 的层级、留白和状态表达，不复制任何第三方品牌资产。

## 当前交付范围

- 主聊天界面重做：顶栏、消息流、助手回合、输入区、状态提示。
- 用户和助手消息渲染分离，工具过程不再追加到普通助手文本中。
- 运行过程默认显示一行摘要，可点击展开工具步骤、结果摘要、错误和耗时。
- 过程卡片采用两级展开：外层展开后步骤默认收起，点击单个步骤查看完整详情；卡片顶部和底部均提供收起整个过程的入口。
- 展开过程后按步骤时间线展示可观察事件、状态图标和完整结果，不把长结果压成固定行数。
- 输入框支持多行、草稿恢复、空闲时随内容启用发送、运行中切换为停止，以及键盘自适应。
- 软键盘弹出时，消息流和输入区跟随 IME inset 重新布局，输入内容和发送按钮保持可见。
- 聊天正文不因气泡行数或字符数被 UI 自动替换为省略号，长消息由外层消息流滚动阅读。
- 本地会话管理：新建、切换、重命名、删除，默认保存最近的有界消息内容。
- 无配置 API、无障碍未开启、悬浮窗未授权等情况使用非阻塞状态提示。
- 跨 App 悬浮窗：获得“显示在其他应用上层”权限后，离开主界面即显示可拖动状态胶囊，不要求先发送任务；空闲时可直接从悬浮窗发送消息。展开后可查看完整消息/过程、发送消息、停止任务、返回主界面或隐藏悬浮窗。展开面板仅标题状态区域负责移动，按钮保留点击语义，右下角使用加粗圆弧提示缩放，不额外放置图标，最小约 `280dp × 240dp`。
- 悬浮窗与主界面使用同一运行状态模型；运行中从悬浮窗发送的消息进入队列，不直接打断当前 Agent 操作。
- 悬浮窗展开内容遵循时间线：用户消息（如有）→ Agent 过程 → 活动记录/排队状态 → Agent 最终回答。最终回答不再固定置于过程上方，长文本保持完整并由面板滚动查看。
- 缩放触控层置于内容层下方，发送按钮和输入框优先响应；右下角圆弧只承担尺寸调整提示和拖动入口。
- 授权模式：设置页提供默认关闭的“全授权模式”，开启后持久化跳过高影响操作确认，并在主界面持续显示安全提示；该模式只建议用于受控测试设备。
- 后台确认：Agent 请求确认时，前台使用 Activity 对话框；Activity 进入后台后迁移为悬浮窗内的确认卡片，显示完整标题、正文和按钮，回到前台后再迁回对话框。
- 不新增生产依赖，不读取或输出真实 API Key，不把真实 LLM 调用加入自动化测试。

## 状态优先级

| 优先级 | 内容 | 默认呈现 |
|---:|---|---|
| 1 | 最新用户消息、最新助手回答 | 主界面始终显示；悬浮窗按任务时间线显示 |
| 2 | 发送/停止、等待确认、失败 | 始终可见 |
| 3 | 当前运行阶段 | 过程卡片一行摘要 |
| 4 | 工具名、耗时、结果摘要 | 点击过程卡片展开 |
| 5 | 完整工具输入输出 | 仅在详情中展示，必要时支持复制 |
| 6 | API、权限、Runtime 能力 | 顶栏状态或设置页 |

## 交互状态验收

| 场景 | 预期 |
|---|---|
| 空会话 | 有明确的开始提示和 2–3 个本地示例入口，不显示空白终端区域 |
| 输入 | 可输入多行，发送按钮随内容启用，键盘不遮挡输入区 |
| 运行中 | 发送变为停止，消息流自动跟随最新内容，过程卡片默认收起 |
| 工具调用 | 显示“正在调用工具”，不把原始 JSON 插入普通聊天正文 |
| 确认 | 前台显示高影响操作确认上下文；后台显示悬浮窗确认卡片；取消后显示可理解的取消结果 |
| 工具完成 | 显示成功/失败和结果摘要，详情可展开 |
| 最终回答 | 清晰显示为助手回合，可继续发送下一条消息 |
| 失败/停止 | 显示原因和可选重试，不伪装成正常完成 |
| 新建会话 | 当前会话先保存，新的 AgentSession 与消息流独立 |
| 返回前台 | 当前会话、草稿和界面状态不表现为重启 |
| 无权限 | 主聊天仍可用，状态提示提供设置入口，不阻塞所有功能 |
| 悬浮窗任务完成 | 过程和活动记录在前，最终回答在后；发送按钮仍可点击，圆角缩放区不遮挡输入操作 |

## 模块计划

1. `DemoConversationStore`：本地会话数据、JSON 编码、有界保存和 CRUD。
2. `DemoRunState`：把 `AgentEvent` 映射为稳定的 UI 状态和过程步骤。
3. `MainActivity`：只负责生命周期、运行协调器绑定和 UI 组装，消息/过程渲染使用独立组件。
4. `DemoAgentRunCoordinator`：持有进程级 Agent Job、运行代次、队列和完成待处理结果，Activity 重建只重新绑定观察者。
5. `AgentFloatingWindow`：消费同一运行状态摘要；活动记录仅作为兼容性辅助信息，不与最终回答混为同一正文层。
6. 测试：Store/排序单元测试、运行状态 reducer 单元测试、Activity 生命周期与现有 Agent 集成回归。

## 性能与安全边界

- 保持原生 View 实现，不为一次 Demo 重构引入新的 UI 框架或生产依赖。
- 主线程只做有限的 View 更新；运行逻辑移出 Activity，长文本与历史均有界，持久化仍需在真机长会话中关注帧耗时。
- 过程和历史都使用有界列表，防止长期测试导致布局无限增长。
- 该界面不把 Terminal Runtime 描述为安全沙箱；工具确认和共享 UID 边界继续由 SDK 负责。

## 2026-08-25 屏幕自动化调优

- `screen_read_ui_tree` 现在返回 `screenWidth`、`screenHeight`、非自身 `windowCount` 和 `truncated`，并支持有界的 `max_nodes`（默认 200，最多 500）。Agent 必须在 `truncated=true` 时继续滚动或请求更大的有界结果，不能据此直接判断目标不存在。
- UI 树读取和屏幕动作路径补齐 `AccessibilityNodeInfo` 回收，减少连续读屏/操作时的节点资源积累；`screen_perform_action` 对未知 action 和缺少 `set_text.text` fail-closed，避免误清空输入框。
- `screen_gesture` 根据当前屏幕尺寸计算滑动终点，拒绝缺少或越界的起点，不再依赖固定 `1080×2400` 坐标；手势回调等待改为可取消的协程等待，超时不会阻塞 Tool 执行线程。
- Agent instructions 改为使用最近一次读屏返回的屏幕尺寸和相对位置计算手势坐标。

- demo 不再注册私有 `Screen*Tool` 或重复的屏幕 Skill；SDK 统一提供 read/find/action/gesture/IME/global tools。
- 所有节点动作使用最新 `snapshotId + nodeId`，backend 会重新解析并校验目标；过期节点、窗口变化、目标不可交互和不支持的 action 都 fail-closed。
- 读屏/查找为只读；点击、输入、滚动、手势、按键和全局动作继续经过精确 input confirmation。
- 详细接入契约见 `android-accessibility-screen-automation.md`；真机跨 App 联调仍需用户手动开启 AccessibilityService。
