# 对话教学与操作经验：当前 MVP

更新：2026-09-29。当前 Demo 源码版本为 **`1.13.0 / 126`**。本轮采用“用户分段对话 → Agent 执行当前段 → 用户纠正或继续 → 结束保存记录 → 用户明确整理经验”的流程。基础实现由 `efacf1b` 保存，深度审查修复已提交为 `b8db716` 并随 `demo-app-v1.13.0` 标签保存；Play 发布推进状态见[版本台账](demo-app-version-ledger.md)。当前测试数量、设备证据和未解决项统一见[版本台账](demo-app-version-ledger.md)。

## 当前用户流程

入口仍为“添加与工具 → 教我操作”。开始教学必须配置模型、由用户在设置中开启全授权模式，并具备已连接的无障碍服务、悬浮窗权限和可交互的解锁屏幕。全授权关闭时，开始页提供直达开关的入口并禁止开始，返回后重新检查；App 不自动替用户打开。截图依赖 Android 11 / API 30+；App 的 minSdk 24 不代表低版本具备该教学能力。配置完整不等于已验证模型的图片能力。

开始后回到手机主页，展开原有悬浮聊天窗并显示教学状态。教学使用普通悬浮窗，不创建全屏触摸保护层，窗外屏幕保持正常交互。用户通过对话描述下一段，例如“打开应用 A”；窗口外观、大小、拖动、展开/收起及运行交互与普通对话退到后台的悬浮窗一致。教学不再使用独立圆形小球、强制贴边或段结束自动展开。关闭只隐藏窗口，返回按钮正常回到App，结束教学通过明确的结束入口。一段可以包含完成当前指令所需的连续工具操作，不要求用户每点一次就填写截图复盘表。

悬浮窗展开/收起采用串行横向滑动：小块向最近左右边缘完全滑出后，对话窗从同侧屏外滑入；收起时反向执行。窗口从首次挂载起保持完全不透明及原尺寸，目标窗口直接在屏幕外创建，不缩放或改变透明度，转换仅临时允许原尺寸窗口越过屏幕边界。动画期间由根View消费自身触摸，不设置FLAG_NOT_TOUCHABLE，以免系统将窗口不透明度强制降到0.8；窗外触摸仍正常。相同方向请求不会打断动画，反向请求排队，隐藏会取消转换并恢复位置参数且不重建窗口。转换期间冻结键盘避让造成的位置/尺寸变化，展开完成后重新同步键盘。屏幕工具仍等待完整转换完成并移除窗口后执行。

用户发现错误时直接在聊天中纠正；新消息与之前的执行记录保留在同一次教学中。模型指令限定其只完成当前段，不自行推演或启动下一段。悬浮窗“停止”只中断本段，清理后仍可继续教学；“结束教学”终止整个教学并保存本地记录。已派发给 Android 的动作不能承诺撤回，停止后的不确定结果不能记作成功。

结束本身不自动调用整理模型。用户查看记录后明确选择整理，才额外发送这次真实对话、工具结果和有界截图证据。整理得到目标、准备条件、有效步骤、纠正经验、完成检查和待核实项，并生成同义意图、目标应用和不适用范围。失败或取消保留原记录。普通用户对话可通过经验工具检索相近记录，展示确认后才读取具体步骤，复用仍需观察当前页面并遵守当前指令。经验也可复制；不按旧坐标重放、不为每份记录安装独立skill，不接入后台定时复用。

视觉手势不按固定15秒淘汰观察，也不在点击前截屏比对像素，页面动画不再触发帧差拦截。保留会话观察ID、目标App、屏幕尺寸/旋转和坐标边界检查；窗口完成收起移除后发送手势。动作后画面比较只作诊断，不作为下一次点击的像素门禁，已执行观察不能再次用于手势。

### 教学恢复与经验复用

教学记录详情支持“接着上次继续教学”。用户确认后，复用原记录ID并追加新段落，保留历史对话、工具状态、截图和纠正内容；重建独立Agent会话，不复原失效的工具调用/坐标。恢复不触发模型或自动重放，等待用户下一条指令，第一项屏幕操作前必须成功读取当前页面。原整理经验保留供查看，但版本失效并退出推荐，重新整理后再验证。教学/整理中的记录与容量已满记录不能续教；历史文字超过120000字符时明确拒绝，不静默丢弃纠正内容。

预制文件型 `teaching-experience/SKILL.md` 与 `DemoTeachingExperiencePlugin` 配合：`teaching_experience_search` 本地检索名称、目标、别名、应用和步骤，使用中文双字片段及英文词排序，返回最多5份摘要；由模型判断语义适用性，不承诺任意同义表达都能召回。`teaching_experience_use` 绑定记录版本和当前用户请求，始终要求实际用户选择，不能被全授权跳过；历史消息压缩不会使本轮授权失效。拒绝、弹窗丢失、停用或版本变化不返回步骤。检查应用更新不授权安装更新。

整理状态为未整理/整理中/已整理/整理失败；使用状态为待验证/可用/需修订/停用。旧记录兼容读取，旧经验默认待验证；重新整理递增版本并重新验证。详情可停用、恢复待验证、标记需修订，并显示最近使用结果。工具只推荐已整理且待验证或可用的经验。

`teaching_experience_report` 只接受已确认、并绑定同一会话和当前用户回合的使用凭据，拒绝旧版本和重复反馈。模型报告成功后，用户核对完成标准并明确确认才标记该版本可用；仅工具手势成功不足以证明任务完成。网络或普通失败保留原可用状态，明确路径失效才标为需修订。中断反馈无法完成时不推定成功。教学录制自身与后台任务不注册经验使用工具，避免循环调用。

## 运行时与界面边界

| 组件 | 职责 |
|---|---|
| [DemoTeachingController](../demo-app/src/main/java/com/ugk/pi/android/testapp/DemoTeachingController.kt) | 独立 AgentSession、逐段执行、停止本段与结束、工具前后 hooks |
| `DemoProcessScope`、`DemoAgentRuntimeFactory`、`DemoAgentRunCoordinator` | 进程持有教学、模型及权限门禁、正常 Runtime 装配与收尾 |
| `AgentFloatingWindow` | 普通/教学共用的悬浮聊天入口、展开收起动效及教学状态；段结束保持当前窗口形态 |
| [DemoTeachingStore](../demo-app/src/main/java/com/ugk/pi/android/testapp/DemoTeachingStore.kt) | 独立 record、分段指令、真实工具结果、截图引用与恢复 |
| [DemoTeachingCompiler](../demo-app/src/main/java/com/ugk/pi/android/testapp/DemoTeachingCompiler.kt) | 用户明确发起的一次有界模型整理，产物为文字经验 |

教学复用 `AgentRuntime` 的模型与工具循环，使用独立会话，避免污染原普通聊天；不接计时意图路由。按用户最新要求，全授权成为开始教学的前置条件，复用已有设置及工具策略，减少录制过程中的逐次确认。教学不会自动修改授权开关；普通任务仍遵守用户当前设置，整理产物本身不改变授权。

教学在整个会话期间持有共享屏幕 owner，包括等待下一条指令时；只有其绑定的 interlock 可以启动教学回合。普通 Agent、旧录制和旧工作流不能抢占屏幕。活动中的普通 Agent（包括思考阶段）、计时或待处理交互按宿主门禁阻止开新教学。Activity 附着与解绑只更新视图，不把教学会话放在 Activity 生命周期内。

普通对话和教学共用屏幕工具装饰器管理悬浮窗：等待收起动画、移除窗口、执行屏幕读取或手势，再在不可取消的收尾中恢复。启动其他 App 的 launch_android_app 和 launch_android_app_intent 保留可见窗口，因为 Android 可能因后台启动规则静默阻止请求，移除唯一可见窗口会复现此问题。教学只在同一保护范围内采集前后证据，不创建全屏触摸保护层，不修改触摸穿透标志。工具期间的后台显示请求会延后兑现，返回主界面则取消恢复请求。共享屏幕 owner 只约束 App 内其它 Agent 回合，不阻止用户触摸窗外的目标 App；系统页面仍可能按系统规则隐藏悬浮窗。

## 记录与整理证据

记录保留每段用户指令、实际工具名称和参数、返回结果与错误状态、可用的前后截图引用，以及该段回答和终态。用户后续纠正保留为新回合，不改写过去发生过的动作。工具成功返回、Agent 声称完成和画面可验证结果是不同证据，整理必须区分；截图缺失、取消、中断或未解决的冲突必须保留为缺口。

教学记录与旧的 `operation-learning` 草稿、`operation-workflows` 计划分开保存，不覆盖旧文件。每次更新形成持久检查点；下次读取会把未结束记录标为中断，不自动继续操作。当前记录存储限制为20份、每份最多80段和600个动作；截图最多120张、每张2MB。达到限制时不静默淘汰旧记录。

整理向模型提供实际记录和最多20张可用截图，图片总量不超过12MB；较多截图会选择代表图，缺失或未发送的图片不能被描述为已核实。记录文本超过本轮预算时拒绝请求。整理是一轮无工具请求，最长90秒；输出必须通过字段及长度校验，不能执行操作或生成已授权的可重放脚本。整理失败可由用户重试，不自动追加付费纠错请求。

API 凭据不写入教学素材，工具的 `transientModelContent` 不作为持久记录。记录及截图仍可能包含页面可见信息；教学中的正常模型回合与结束后额外整理是两个不同的请求阶段。本地保存不等于从未向模型发送内容，也不代表任务已成功。

## 兼容边界与未解决问题

旧手动录制草稿和已有工作流继续保留；它们不是新对话教学记录，不自动迁移成教学成功步骤。分段对话才是当前教学主流程；旧的逐步人工确认、试跑和受限工作流仍用于兼容旧记录，不作为新经验的自动执行能力。

Google Play“管理应用和设备”的视觉手势仍未确认有效：已观察到无障碍派发回调完成而页面不跳转；用户在另一款 App 的点击成功，且同坐标 ADB 输入有效。Android 16 的敏感 View 探针只能证明系统可能出现这种现象，不能证明 Play 目标控件具有同一属性；详细诊断见[版本台账](demo-app-version-ledger.md)。

历史版本验收数据和本轮实际执行的检查命令统一维护在[版本台账](demo-app-version-ledger.md)。旧版本的测试数量不能充当当前工作树的验证结果；未实际执行的检查不得写成通过。
