## 当前用户流程

入口仍为“添加与工具 → 教我操作”。开始教学必须配置模型、由用户在设置中开启全授权模式，并具备已连接的无障碍服务、悬浮窗权限和可交互的解锁屏幕。全授权关闭时，开始页提供直达开关的入口并禁止开始，返回后重新检查；App 不自动替用户打开。截图依赖 Android 11 / API 30+；App 的 minSdk 24 不代表低版本具备该教学能力。配置完整不等于已验证模型的图片能力。

开始后回到手机主页，展开原有悬浮聊天窗并显示教学状态。教学使用普通悬浮窗，不创建全屏触摸保护层，窗外屏幕保持正常交互。用户通过对话描述下一段，例如“打开应用 A”；窗口外观、大小、拖动、展开/收起及运行交互与普通对话退到后台的悬浮窗一致。教学不再使用独立圆形小球、强制贴边或段结束自动展开。关闭只隐藏窗口，返回按钮正常回到App，结束教学通过明确的结束入口。一段可以包含完成当前指令所需的连续工具操作，不要求用户每点一次就填写截图复盘表。

悬浮窗展开/收起采用串行横向滑动：小块向最近左右边缘完全滑出后，对话窗从同侧屏外滑入；收起时反向执行。窗口从首次挂载起保持完全不透明及原尺寸，目标窗口直接在屏幕外创建，不缩放或改变透明度，转换仅临时允许原尺寸窗口越过屏幕边界。动画期间由根View消费自身触摸，不设置FLAG_NOT_TOUCHABLE，以免系统将窗口不透明度强制降到0.8；窗外触摸仍正常。相同方向请求不会打断动画，反向请求排队，隐藏会取消转换并恢复位置参数且不重建窗口。转换期间冻结键盘避让造成的位置/尺寸变化，展开完成后重新同步键盘。屏幕工具仍等待完整转换完成并移除窗口后执行。

用户发现错误时直接在聊天中纠正；新消息与之前的执行记录保留在同一次教学中。模型指令限定其只完成当前段，不自行推演或启动下一段。悬浮窗“停止”只中断本段，清理后仍可继续教学；“结束教学”终止整个教学并保存本地记录。已派发给 Android 的动作不能承诺撤回，停止后的不确定结果不能记作成功。

结束本身不自动调用整理模型。用户查看记录后明确选择整理，先按教学段及操作顺序清理已知结构中的重复字段，再发送教学指令、工具结果和有界截图证据。短记录直接整理；长记录按教学段分批提炼事实、纠正、完成证据及待核实项，必要时再合并摘要，最后统一整理有效路径。单段过长时按动作拆批，每批重复该段指令、回答和状态；极长单项材料以带背景的原文分片送入，不用首尾截取代替中间证据。界面提示当前批次，支持取消，并提前说明多次模型请求和耗时。原始教学记录与截图不修改。

最终经验是一份自然语言 Markdown SOP。整理模型根据证据填写步骤笔记并编写指南，随后独立的审核 Agent 对照原始指令及证据核对目标、顺序、纠正和完成条件；可自主回查原批次及截图、修订正文，通过 submit_reviewed_sop 明确交付。程序不以固定 JSON 字段、步骤数量或标题格式判断内容质量。建议正文说明目标、准备条件、操作步骤、纠正、完成检查和待核实项；后续纠正可能撤销前段目标，审核须全局核对。普通用户对话可检索相近经验，用户确认后才读取完整正文，复用仍需观察当前页面并遵守当前指令。经验也可复制；不按旧坐标重放、不为每份记录安装独立skill，不接入后台定时复用。

教学详情分为记录概况、最佳实践和教学过程。整理为主操作，继续教学为次操作；复制、经验状态管理和删除收进右上角更多菜单。每段默认展示指令摘要及操作/画面数量，回复、完整指令及证据说明可展开。整理确认沿用教学经验纸张样式；处理期间以不可返回/点外部关闭的模态弹窗展示实际阶段、已完成批次和用时，不使用估算百分比。无需执行的阶段明确标为跳过。完成后关闭并刷新记录，失败保留原因与重试入口；主动取消可返回页面，底层请求尚未退出时显示正在取消并阻止重复发起。

视觉手势不按固定15秒淘汰观察，也不在点击前截屏比对像素，页面动画不再触发帧差拦截。保留会话观察ID、目标App、屏幕尺寸/旋转和坐标边界检查；窗口完成收起移除后发送手势。动作后画面比较只作诊断，不作为下一次点击的像素门禁，已执行观察不能再次用于手势。

### 教学恢复与经验复用

教学记录详情支持“接着上次继续教学”。用户确认后，复用原记录ID并追加新段落，保留历史对话、工具状态、截图和纠正内容；重建独立Agent会话，不复原失效的工具调用/坐标。恢复不触发模型或自动重放，等待用户下一条指令，第一项屏幕操作前必须成功读取当前页面。原整理经验保留供查看，但版本失效并退出推荐，重新整理后再验证。教学/整理中的记录与容量已满记录不能续教；历史文字超过120000字符时明确拒绝，不静默丢弃纠正内容。

预制文件型 `teaching-experience/SKILL.md` 与 `DemoTeachingExperiencePlugin` 配合：`teaching_experience_search` 本地检索名称、目标、别名、应用、旧步骤及新正文，使用中文双字片段及英文词排序，返回最多5份有界摘要，不提前返回正文或完整步骤；由模型判断语义适用性，不承诺任意同义表达都能召回。`teaching_experience_use` 绑定记录版本和当前用户请求，始终要求实际用户选择，不能被全授权跳过；历史消息压缩不会使本轮授权失效。批准后 document 非空时以完整正文为准，其余字段仅为可选检索提示。拒绝、弹窗丢失、停用或版本变化不返回步骤。检查应用更新不授权安装更新。

整理状态为未整理/整理中/已整理/整理失败；使用状态为待验证/可用/需修订/停用。旧记录兼容读取，旧经验默认待验证；重新整理递增版本并重新验证。详情可停用、恢复待验证、标记需修订，并显示最近使用结果。工具只推荐已整理且待验证或可用的经验。

`teaching_experience_report` 只接受已确认、并绑定同一会话和当前用户回合的使用凭据，拒绝旧版本和重复反馈。模型报告成功后，用户核对完成标准并明确确认才标记该版本可用；仅工具手势成功不足以证明任务完成。网络或普通失败保留原可用状态，明确路径失效才标为需修订。中断反馈无法完成时不推定成功。教学录制自身与后台任务不注册经验使用工具，避免循环调用。

教学复用 `AgentRuntime` 的模型与工具循环，使用独立会话，避免污染原普通聊天；不接计时意图路由。按用户最新要求，全授权成为开始教学的前置条件，复用已有设置及工具策略，减少录制过程中的逐次确认。教学不会自动修改授权开关；普通任务仍遵守用户当前设置，整理产物本身不改变授权。

教学在整个会话期间持有共享屏幕 owner，包括等待下一条指令时；只有其绑定的 interlock 可以启动教学回合。普通 Agent、旧录制和旧工作流不能抢占屏幕。活动中的普通 Agent（包括思考阶段）、计时或待处理交互按宿主门禁阻止开新教学。Activity 附着与解绑只更新视图，不把教学会话放在 Activity 生命周期内。

普通对话和教学共用屏幕工具装饰器管理悬浮窗：等待收起动画、移除窗口、执行屏幕读取或手势，再在不可取消的收尾中恢复。启动其他 App 的 launch_android_app 和 launch_android_app_intent 保留可见窗口，因为 Android 可能因后台启动规则静默阻止请求，移除唯一可见窗口会复现此问题。教学只在同一保护范围内采集前后证据，不创建全屏触摸保护层，不修改触摸穿透标志。工具期间的后台显示请求会延后兑现，返回主界面则取消恢复请求。共享屏幕 owner 只约束 App 内其它 Agent 回合，不阻止用户触摸窗外的目标 App；系统页面仍可能按系统规则隐藏悬浮窗。

## 教学整理专用 Skill

整理方法位于 APK 资源 [teaching-skills/teaching-sop-author](../demo-app/src/main/assets/teaching-skills/teaching-sop-author/SKILL.md)。一次整理从资源加载一个快照，各阶段使用公共正文与当前阶段 reference：提炼、合并使用 `step-notes.md`，编写使用 `write-sop.md`，审核使用 `review-sop.md`。提炼、合并、编写的直接模型请求通过 `AndroidSkillPromptBuilder` 注入；独立审核 Runtime 必选此 Skill，不依赖模型自行发现或调用 `skill_read`。

该 Skill 指导整理 Agent 编写经验，与普通聊天中检索、获准使用已有经验的 `teaching-experience` Skill 分工不同。它不进入通用 `agent-skills/` 或 `AgentSkillSeeder`，不会注入普通聊天。阶段模板只是写作建议，内容质量、证据取舍与必要回查由 Agent 判断；程序继续管理请求、容量、取消、检查点及 `submit_reviewed_sop` 明确交付，不恢复固定格式审核。

## 记录与整理证据

记录保留每段用户指令、实际工具名称和参数、返回结果与错误状态、可用的前后截图引用，以及该段回答和终态。用户后续纠正保留为新回合，不改写过去发生过的动作。工具成功返回、Agent 声称完成和画面可验证结果是不同证据，整理必须区分；截图缺失、取消、中断或未解决的冲突必须保留为缺口。

教学记录与旧的 `operation-learning` 草稿、`operation-workflows` 计划分开保存，不覆盖旧文件。每次更新形成持久检查点；下次读取会把未结束记录标为中断，不自动继续操作。当前记录存储限制为20份、每份最多80段和600个动作，且整份记录编码不超过4MB；两条限制谁先到都按“已达上限”报告而不是写成保存失败。证据写入在距上限 512KB 处停止增长，留下的余量用于存放整理结果与结束状态，因此记录被容量拒绝后仍然可以结束教学并保存经验。截图最多120张、每张2MB。达到限制时不静默淘汰旧记录。

本地清理仅移除持久化元数据和已知工具的非语义字段，或把结构树节点的重复包名提升为共同默认值。保留全部节点、顺序、状态、操作参数、错误、缺口及未知内容，不跨批次删除重复观察。截图工具的观察ID、动作的 effectVerified、结果中的 truncated 等证据保持可见。历史记录保存时已有的工具结果 12,000 字符截断无法还原，达到此长度的结果会标记为可能不完整，不能推断缺失部分。

整理最多选择20张可用截图，一次教学加载的原图合计不超过12MB；较多截图会等距采样。发送给模型时按“单次请求”限制附图：一次请求的截图 Base64 文字不超过4,000,000字符（约3MB原图），因为进入请求体的是编码文字而不是文件本身。被上限挡下的截图不会谎报为已发送——笔记包装只记录实际附过的名称，回查工具另外返回 `imagesAvailable`（该批真实持有数量）与 `imagesSupplied`（本次实发数量），并在诊断中记录 `images_budget_dropped`。长记录的图像先发送给对应步骤的首次笔记请求；合并与草稿沿用此前观察及缺口。审核 Agent 按需要回查原材料时可重新查看所选截图，原文及图片以 transientModelContent/images 进入紧邻的模型请求，不写入审核会话历史。缺图、未验证动作、取消、中断及失败不能变为已完成。

审核回查使用 index/offset 分页：每页最多12,000字符，同一模型轮的原文总量最多24,000字符，并明确返回 total/nextOffset；超出本轮容量的调用告知尚未读取，可下一轮续读。默认不附图，Agent 显式 includeImages=true 时每轮至多附一批，避免多个工具结果堆成一次大型图文请求。分页仅管理上下文容量，审核内容及需要回查哪些证据仍由 Agent 决定。

原始材料每批上限48,000字符、最多6张实际附图；最终汇总材料可追加不超过32,000字符的完整指令清单，笔记/草稿请求文字守卫为96,000字符。笔记按完整条目合并，必要时保留原文分片，最多五轮。每次请求使用210秒协程超时、180秒底层读取时限；教学 Provider、Compiler 与审核包装均透传 SDK 流式响应，取消时 SDK 主动断开连接。步骤笔记与草稿不提供工具或隐式重试，审核 Agent 使用 SDK 工具循环，可根据工具反馈修订，含不完整响应重试在内最多12次模型请求，普通回答未交付时最多提醒一次。取消后不再发起后续批次，收尾前仍阻止重复启动。只有审核 Agent 明确交付才保存最终经验，失败保留原记录与检查点；保存开始前检查取消，原子保存完成后不再被取消状态覆盖。Activity 销毁会请求取消，进程内编译器排他与记录状态共同阻止重复整理。这里只交付文字 SOP。

新整理流程使用普通文字响应，模型正文不经过业务 JSON 解析；程序负责将文字安全序列化到本地文件。只检查请求完整性、非空及容量边界，截断/安全中止不能冒充审核通过。交付工具只接收正文及简短审核说明，不机械校验步骤措辞或小节。应用私有诊断只记录有界的阶段、接口协议、耗时、字符数、停止原因及错误码，不记录请求/响应正文、推理内容或凭据。旧结构化经验继续读取，新 document 为可选字段；展示、复制与获准复用均优先完整正文。

教学专用请求错误统一转换为安全异常，保留 HTTP 状态、正文中明确提供的短服务错误码/请求编号，以及 DNS、连接、TLS、超时等类别；原始服务端 error.message 和响应正文不直接显示或写日志。Runtime Failed 不再把普通网络异常替换成“Agent 核对尚未完成”；没有 HTTP 信息时不猜测额度或限流，响应头专有的请求编号因现有 transport 未提供 headers 而不可读取。流式开始、请求失败及审核失败分别留元数据检查点。

已完成的步骤笔记和 SOP 草稿单独原子保存，按模型端点/配置、实际注入的提示词、材料、缓存格式及图片内容指纹匹配；Skill 公共正文或阶段参考变化会使对应检查点重新生成。指纹一致时，用户再次整理可复用检查点，审核仍需重新完成。Skill 更新不删除原始教学记录或已有经验。缓存每份记录最多512KiB，缓存读写失败不覆盖原始记录；升级前失败请求的正文没有缓存，不能恢复此前已消耗的请求。

教学整理使用独立 Provider 适配，仅官方 open.bigmodel.cn 的 OpenAI 协议 GLM-5.3 / Flash / FlashX 请求补 max_tokens、reasoning_effort=low 和 thinking=enabled。依据[智谱官方迁移说明](https://docs.bigmodel.cn/cn/guide/start/migrate-to-glm-new)与[GLM-5.3-Flash 文档](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)。2026-09-29 最新核对发现用户实际配置走 Anthropic 兼容路径，原 SDK 已传 max_tokens，上一轮将其当作 OpenAI 路径分析有误；上述适配不作用于该配置。新自然语言流程不依赖任一接口提供 JSON 模式。普通对话、SDK Provider 和用户保存的配置不修改。

API 凭据不写入教学素材，工具的 `transientModelContent` 不作为持久记录。记录及截图仍可能包含页面可见信息；教学中的正常模型回合与结束后额外整理是两个不同的请求阶段。本地保存不等于从未向模型发送内容，也不代表任务已成功。

## 兼容边界与未解决问题

旧手动录制草稿和已有工作流继续保留；它们不是新对话教学记录，不自动迁移成教学成功步骤。分段对话才是当前教学主流程；旧的逐步人工确认、试跑和受限工作流仍用于兼容旧记录，不作为新经验的自动执行能力。

Google Play“管理应用和设备”的视觉手势仍未确认有效：已观察到无障碍派发回调完成而页面不跳转；用户在另一款 App 的点击成功，且同坐标 ADB 输入有效。Android 16 的敏感 View 探针只能证明系统可能出现这种现象，不能证明 Play 目标控件具有同一属性；详细诊断见[版本台账](demo-app-version-ledger.md)。

历史版本验收数据和本阶段实际执行的检查命令统一维护在[版本台账](demo-app-version-ledger.md)。旧版本及本阶段较早轮次的测试数量不能充当最新实现的验证结果；未实际执行的检查不得写成通过。
