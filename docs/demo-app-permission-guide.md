## 展示与生命周期

- 用户明确要求“每一次进去”检查，优先于 `app-onboarding/SKILL.md` 的“版本号门禁”与“存量用户永久旁路”。新老用户都按系统实时状态判断；不以“已看过引导”永久跳过。通知等便利权限也按本次用户的完整能力引导要求纳入。
- 一次前台进入中，每个环节最多请求一次系统授权框；系统不再询问时可以接续一次设置入口。通知总开关开启后若提醒分类仍关闭，接续说明分类；普通拒绝或从设置返回未开启则继续，不能循环。已授权项目自动略过。支持跳过当前项，以及返回键/关闭入口结束本次引导；下一次从后台重新进入时再检查。
- 从权限设置返回属于当前流程，不能重头开始；系统授权框、相册/相机/文件选择、App 内设置往返和 Activity 重建也不得被误判为新的进入。重建期间保存本轮尝试和待返回状态，重新查询真实权限。
- Agent 正在运行、等待确认、计时或重要提醒交互时，延后引导，优先保留现有任务界面。普通引导不抢占系统权限框或应用更新界面。
- 主按钮只在用户点击后调用系统授权/设置。永久拒绝时给出可用的系统设置入口；打开失败应留有解释与跳过路径。权限状态不以本地偏好替代系统查询。

## 已授权后关闭与不再询问

`DemoRuntimePermissionHistory` 由引导和附件拍照入口共用，沿用旧 `permission_guide_requests` 请求记录，并在实际检查已授权或成功回调时记录曾获授权。当前权限始终重新查询 Android，历史记录不能视为当前授权。

- 未授权、系统允许再次询问时，仍请求系统授权框。无历史记录时也先走正常首次申请。
- 未授权、系统不再给出再次询问的依据，且曾申请或曾获授权时，主按钮与执行逻辑共同选择“去系统设置”。相机进入本应用详情，通知直接进入本应用通知设置。
- 旧版本缺少历史记录、请求又被系统直接拒绝时，保留当前卡片，补充“当前未获得权限，请在系统设置中开启。”并改为设置按钮；等待用户点击，不自动跳设置。设置返回仍未开启则继续后续项目，不重新循环。待返回权限名称与当前兜底阶段随 Bundle 保存。

Android 的公开权限 API 不能可靠区分所有首次申请、手动关闭、一次性授权失效及自动撤销原因，因此界面只说明当前状态，不断言用户主动拒绝。依据：[运行时权限请求与拒绝处理](https://developer.android.com/training/permissions/requesting)、[Android 11 的授权框可见性与一次性权限](https://developer.android.com/about/versions/11/privacy/permissions#dialog-visibility)。

附件拍照入口使用同一判断：不能再次询问时给出可跳过的设置入口；用户明确点击拍照并正常获准时继续打开相机。进入 App 的引导获准则只推进引导，不启动拍照。
