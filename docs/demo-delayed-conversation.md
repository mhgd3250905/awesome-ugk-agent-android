# Demo 单对话延时任务（首版）

更新时间：2026-09-25。本文描述 `demo-app` 当前的延时任务交互；SDK 通用持久化调度器另见 [android-scheduled-tasks.md](android-scheduled-tasks.md)。

## 目标与流程

每条直接用户消息先交给当前配置的大模型作结构化意图判断。模型给出一次性相对延时提案时，宿主把模型提供的时长和到点动作交给现有 `demo_delay_propose` 工具；其他请求继续走原 Agent 工具循环。输入文字和助手回答都不由宿主做延时关键词、正则或格式匹配。模型路由结果缺失或无效时最多重新请求一次，仍无效则明确失败，不创建任务。App 展示任务内容并要求用户明确确认；“全授权”设置不会跳过这一步。计时从确认时开始，不提前执行到点动作。

模型路由是每个直接用户回合的一次额外模型请求。对 Z.AI 官方端点使用其 [JSON 对象输出模式](https://docs.z.ai/api-reference/llm/chat-completion)；其他兼容端要求模型输出 JSON 并严格校验。路由输出只作为内部决策，不显示到对话，也不写入会话记录。到点续跑消息属于 `SCHEDULED_TASK`，直接进入原 Agent 工具循环，避免把批准后的动作再识别成一个新定时任务。

确认后，当前对话进入唯一的等待槽位。确认与等待共用应用主题下的原生卡片：确认态分别展示等待时长、完整任务、后台设置和开始/取消；等待态展示大号倒计时、确定进度、任务、预计触发时间和“停止任务”。长内容与放大字体下卡片可滚动。其他消息、历史切换及新建会话在等待期间被阻止，悬浮窗也不能排队新消息。离开页面或锁屏不会主动取消。到点后，进程级分发器向同一 `DemoConversation` 追加一条用户消息，使用同一个 `AgentSession` 和 `AgentRuntime` 启动普通 Tool/模型循环，并将结果写回该对话。等待和执行中都只占一个槽位。

确认定时任务只授权“稍后发起这个回合”，不等于授权到点后所有高影响工具；原有工具确认和“全授权”策略继续生效。后台没有 Activity 时，原有悬浮窗确认路径可承接需要用户决策的动作。

首版只接受一次性相对延时（1 秒至 24 小时）；不解析 Cron 表达式，不支持重复任务，不为延时创建 JobService、AlarmManager 触发器或独立 Agent 会话。旧 SDK 模块仍保留供其他宿主使用，但 Demo 不再注册 `agent_task_*` 工具。升级时，Demo 停止旧版仍处于 `SCHEDULED` 或 `RUNNING` 的后台任务并在关联对话说明；不会把旧任务悄悄迁成新的等待槽位。

## 进程与故障边界

`DemoDelayedTaskController` 与 `DemoAgentRunCoordinator` 由 `DemoProcessScope` 持有。Activity 只附着状态和展示弹窗；页面销毁不取消任务，悬浮窗的停止命令在没有 Activity 时仍能到达进程级控制器。App 引导用户在设备设置中允许自启动、后台运行并降低电池限制，但不把这些设置当成准点执行保证。

计时以 `SystemClock.elapsedRealtime()` 的截止时间为准。后台进程若暂时得不到执行时间，恢复后检查截止时间并尽快执行一次。进程死亡会终止内存计时与 Agent 运行；本地只存一个中断标记，下次启动明确报告“尚未执行”或“执行结果可能不完整”，绝不自动补跑。用户按“停止任务”会取消等待或当前执行并在对话里记录。

## 接线与验收边界

- `DemoModelIntentRouter`：每个直接用户回合的模型 JSON 路由；只按模型结构化结果选择延时工具或继续原 Agent 流程。
- `DemoDelayAgentPlugin`：延时提案工具、参数校验、首回合结束。
- `DemoDelayedTaskController`：唯一槽位、确认后计时、取消、中断标记。
- `DemoDelayedMessageDispatcher`：到点后追加消息、启动同会话运行、保存结果。
- `DemoDelayedTaskDialog` / `MainActivity`：确认、倒计时、使用阻塞和重新附着。
- `DemoApplication` / Demo Manifest：清理旧任务并移除旧版后台组件入口。

`1.2.0 / 107` 的基本延时流程已获用户真机反馈“功能是可以的”；该反馈同时指出原系统弹窗与无限转圈过于简陋。`1.2.1 / 108` 的确认/等待卡片已在本地 Android 模拟器以浅色和深色分别渲染检查。真机后续诊断发现模型可能只回复“请确认”而不调用工具，导致没有提案及弹窗；`1.3.1 / 110` 曾加入宿主文字兜底，用户明确拒绝此设计，`1.3.2 / 111` 已改为模型路由。进程存活与准点执行边界未改变，不宣称系统级准点或后台存活保证。
